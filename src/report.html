How the classification works

The classification identifies Public Building projects from Infrastructure projects by examining the physical asset and the work described. Each eligible PID receives one classification using project descriptions and related information recorded across the available reporting periods. Project names, scope descriptions, linked budget names and ten-year-plan categories are read together, with the recorded decision reason explaining how that evidence supports the result.

  1. Establish one project record per PID.
  2. Exclusions. Projects with BOE/DOE, CUNY, NYCHA or H+H/HHC sponsorship anywhere in the selected history are excluded.
  3. Identify the physical asset and scope. Agency Project Name, FMS Name, Project Description and 10-Year Plan Category provide complementary evidence. Historical descriptions help interpret abbreviated or incomplete wording in an individual snapshot. Recorded project-specific resolutions are retained alongside that evidence.
  4. Assign Public Building or Infrastructure. Building assets and systems serving their indoor use are classified as Public Building. Outdoor, transport, site and utility assets are classified as Infrastructure.
  5. Assess the work within its setting. A Parks project may involve a building or an outdoor asset. Similarly, work at a wider infrastructure facility may concern an indoor building system.
  6. Needs Review. Projects whose classification remains unresolved are retained as Review. There is no accepted Mixed category in this portfolio.

How to read the analysis measures

  • Phase duration: Actual phase end minus actual phase start, in days.
  • Budget growth: Change from the first observed attributable budget, which may differ from the original approved budget.
  • Budget spent: Spend to date divided by current budget, expressed as a percentage. This measures expenditure rather than physical completion.
  • Forecast slippage: Active forecast completion minus the first observed forecast.
  • Completion delay: Reported actual completion minus a verified pre-completion forecast baseline.
  • Shared funding: A budget may fund several PIDs and a PID may link to several budgets. Shared funding is not assigned in full to each PID. Keep attribution flags visible and do not sum budgets or spending across reporting periods.

Measures describe the latest available project summary. Quality flags identify limitations in the supporting records. Full source inputs and transformation code are needed to verify calculations and reproduce period-by-period analysis. Predictive analysis must also avoid treating later historical evidence as information available at an earlier date.

PREDICTIVE ANALYSIS · SIX-PERIOD HISTORICAL ASSESSMENT

Can recorded information help identify projects whose expected finish date will move later?

We test a random forest using earlier schedule, budget, spending, agency and location records. Before each report, it ranks projects for review; the following report shows whether their expected finish dates moved later.

Results cover six reporting assessments, September 2024–May 2026. The default review list is the highest-ranked 20% in each period.

The model’s review list is more likely to contain projects whose expected finish dates move later. It helps prioritise checks, but cannot confirm which projects will be delayed.

Model and test design

Random forest: 250 trees, maximum depth 6, minimum leaf size 20, random seed 19. Each fold fits again using eligible outcomes from earlier reports only. Numeric inputs use training medians with missing indicators; categories use explicit missing values and one-hot encoding. Settings are held constant across folds.

The master roster contains 2,300 Infrastructure PIDs. Six assessments cover September 2024, January/May/September 2025 and January/May 2026: 5,412 eligible project/report comparisons, with 1,533 later forecasts. The same PID can appear in more than one assessment; these are not 5,412 unique projects. Each fold requires comparable explicitly Forecast dates at both reports. Missing, Actual and untyped date pairs are excluded.

What counts as a flag or a change?

A later forecast means the next report's expected completion date is after the starting report's forecast. Rank projects by model score, break ties by PID, and flag the highest 10%, 20% or 30%, rounded up separately within each period. Scores are not calibrated probabilities; the project list shows ranks.

Flags correct (precision) = correct flags ÷ all flags. Changes found (recall) = correct flags ÷ all later forecasts. The overall later rate uses every eligible comparison. A longer list normally catches more changes and adds false alarms.

Reporting dates and limits

Saved MCP exports were created on 8 November 2026 from the local source build; this is not a fresh upstream download. Each comparison spans adjacent four-month reports. This is retrospective expanding-window evaluation: it improves the view across time but does not create a new independent test after repeated model development. Future reports should confirm performance.

The earlier May 2024 assessment had only two earlier outcome periods available for fitting: 32 of 182 flags were correct (17.6%), below its 20.1% overall rate. The six-period summary starts in September 2024, once more history is available. This early failed check is retained here rather than omitted silently.

This uses the same predictors, random-forest settings and expanding-window design, retrained for a different outcome: forecast completion moves later by at least 90 days at the following report.     Shared methods for the five new analyses

    Logistic regression uses L2 regularisation, C=1 and a fixed seed. Random forest uses 250 trees, maximum depth 6, minimum leaf size 20 and seed 19. Numeric missing values use training medians and missing flags; categories use training-only encoding and rare-category pooling. No future reason, budget, phase, date or target field is supplied as a predictor.

    Classification comparisons review the highest-scored 20%, rounded up, on the same eligible units within each question. Equal scores use a deterministic PID/budget-key order independent of outcomes. Scores rank candidates; they are not calibrated probabilities. Precision is correct flags divided by all flags; share found is correct flags divided by all true cases. Average precision summarises precision–recall performance; ROC AUC measures ranking.

    95% bootstrap intervals use 400 final-test unit resamples at fixed flag membership. They omit training and period uncertainty. Shared financial records introduce further dependence. Duration assessment uses newly observed actual phase completions, not random rows; a PID can contribute more than one different phase. Quantile regressors use 100 boosting stages, depth 2, minimum leaf size 10 and seed 19, with quantiles sorted to avoid crossing. The earlier validation comparison is retained in the downloadable analysis outputs.

    No composite watchlist is reintroduced. These are additional historical predictive analyses, with new targets and explicit samples.
